01 / positioning

解决“会话会消失”的协作问题

一次性 shell 命令无法长期保持 IRC 连接；长期连接若不随 Agent 会话退出，又会留下占用昵称、无人读取的幽灵客户端。本功能同时解决可靠连接与安全归属。

它是什么

可信环境内的 Agent 协作总线

  • • 频道用于发现、公告与多人讨论
  • • 私信用于一对一任务与答复
  • • CLI 和 SKILL 共同规范会话行为

它不是什么

不是重写 IRC 或 A2A

  • • 不实现原生 IRC 协议，继续使用 ii
  • • 没有 AgentCard、任务状态机或跨组织认证
  • • 不负责常驻服务运维与手动 refresh 伴随技能

关键含义

先把安全的小闭环做实

  • • ii / ngircd 是显式系统前置条件
  • • 无 TLS/认证配置不得暴露到不可信网络
  • • 每个 worktree 默认拥有独立 client home 与游标

02 / MVP core loop

先确认“谁拥有连接”，再允许协作

MVP 不以“能发一条消息”为完成标准。必须确认运行中的 Agent 是可验证 owner，且频道成员关系已被服务器确认；否则命名失败原因，而不是盲目写 FIFO。

启动

记录昵称、角色、频道、owner 绑定与游标；同路径外来 session 不可静默接管。

日常协作

所有操作先经过 Ensure：检查 owner、supervisor、FIFO 读者、/TIME 与 /NAMES。

结束与清理

owner 退出时 supervisor 带走 ii；gc 只处理可证明失效的客户端。

03 / architecture

Go 管生命周期；ii 管 IRC

设计刻意不把 IRC 协议搬进 chatta。Go 层负责状态、并发与安全；ii 提供 FIFO/会话文件布局，ngircd 提供消息总线。

参数、帮助、标准输出/错误输出；不复制生命周期逻辑。

控制层

状态验证、进程身份、恢复、消息、watch 与 fleet 管理。

04 / session model

持久化协作上下文，不把它做成常驻服务

stateDiagram-v2
  [*] --> Starting
  Starting --> Active: ii 运行且加入 home channel
  Starting --> Stopped: 启动失败
  Active --> Recovering: FIFO 或连接异常
  Recovering --> Active: 重启并确认 NAMES
  Active --> Stopping: 显式 stop
  Stopping --> Stopped: 进程组已退出
  Active --> Orphaned: owner 心跳消失
  Recovering --> Orphaned: owner 心跳消失
  Orphaned --> Cleaned: gc 证明已失效
实体关键字段 / 规则
ChatSession昵称、角色、host/port、home channel、已加入频道、owner、supervisor、启动时间。
OwnerBindingPID + StartFingerprint 同时匹配才存活，避免 PID 复用误杀。
Conversation / Cursor动态发现频道与私信目录；游标按调用 Agent session 隔离，日志缩短时安全重置。
ClientSurvey为 clients/gc 汇总状态；live owner 永不清理。

05 / public contract

一组面向 Agent 的 CLI，而非一套隐式脚本

根命令的 --config、--verbose 和 version 不变。Chat 配置优先级：flag → CHATTA_CHAT_* → 配置文件 → 兼容的 AGENT_CHAT_* → 默认值。

命令族主要命令可观察语义
会话session start <nick> [role] [--takeover]
session status · session stop [--force]		绑定可验证 owner；健康逐链路输出；外来 live owner 需显式授权。
频道与消息channel join|leave|members
message send [-c] · message direct <nick> <text>		按 Channel Membership 与 Message 模型操作；只向已确认加入频道发送。
收件箱inbox read [--all] · inbox watch按调用会话的游标读取；标注来源、过滤 self echo，并在长运行时检查恢复。
本机客户端client list · client gc [--dry-run] [--prune]检查全部 client home；仅处理已证明结束/无主的会话与 stray client。
--home 独立 client home --host / --port 总线位置 --channel home channel --ii 显式 ii 路径

06 / user value

四个增量：先有在场，再有协作，再有韧性

US1 · P1MVP

持久且可归属的会话

worktree 隔离、owner 心跳、健康检查、显式 takeover 与退出时连带清理。

US2 · P1协作闭环

频道、私信与可读收件箱

成员确认、DM 缺席失败、独立游标、来源标签与 self echo 过滤。

US3 · P2韧性

中断后恢复而不盲发

恢复 client 和频道，确认 NAMES 后再发送；安全 survey 与 gc。

US4 · P2可移植使用

仓库内的 chat SKILL

把身份、频道、消息标签、回复策略、watch/poll 与信任边界随 CLI 一起交付。

08 / boundary & risk register

明确当前可接受的限制，避免把便利误认为安全

边界 / 风险当前处理本期之外的扩展方向
公网或多租户暴露模板只监听 127.0.0.1；无 TLS/认证，私有 LAN 必须用户主动配置。信任边界变化后，再评估认证、TLS、访问控制与服务运维。
PID 复用 / 误杀PID + 启动指纹；只对确认的 hidden supervisor / ii 进程组发信号。持续保持进程身份测试，不能退化为 PID-only 清理。
ii 连接中断统一 Ensure，先修复频道，再用 TIME/NAMES 验证后发送。真实 daemon 烟测持续约束 ii 的文件与响应语义。
平台差异首版限定 macOS/Linux POSIX，锁、FIFO、进程组放在平台文件。需要 Windows 时，先重新定义 transport 与生命周期约束。
A2A 误解SKILL 保留 A2A 对比：IRC 有低成本群组通信，但没有 AgentCard、任务状态与认证。若需要这些能力，应作为独立协议/服务能力评估。

09 / scope trade-off

从独立脚本到仓库能力：保留行为，收缩运行时复杂度

原有形态

独立 Python wrapper + 分散 skill 资产

  • • 生命周期、FIFO、状态和测试不在当前 CLI 项目内
  • • 使用方需要记住脚本路径与外围资源
  • • 安全不变量难以受本项目测试保护

本期目标形态

Go CLI + 同仓库 SKILL + 外部 ii/ngircd

  • • 保留 ii 的 transport 语义，不重写 IRC
  • • 用 chatta 统一状态、恢复、测试与文档入口
  • • 用 owner binding、锁和保守 gc 保留安全目标
